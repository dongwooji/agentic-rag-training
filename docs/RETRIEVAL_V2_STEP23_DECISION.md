# Step 2/3 변경 결정: 검색어 생성과 동결본 번역

결정 시점은 Retrieval 검색 이전이다. 기존 Phase A 검증 감사가 변경 이유이며 검색 지표를 보고 설계를 바꾸지 않았다.

## 2026-10-10 prompt 재검토 결정

- 교체 사실과 이유: **평가 데이터 유래 예시 제거**. 분리용 prompt의 문헌 주제 예시를 사용자가 제안한
  고령자의 근감소 예방으로 교체하고, 연구 조건 숫자 예시를 세트 간 2분 휴식·주 2회 훈련·8~12회 반복으로 교체했다.
  Step 2 검증 안내·명세와 검색어 준비 테스트에도 같은 기준을 적용했다. 테스트에는 별도의 합성 수치·기호를 사용한다.
- 예시 교체를 위해 dev/dev-ko/held-out 질문이나 Gold를 열람하지 않았다. held-out과의 비교를 위해 열람하지도 않는다.
- Step 2에서 바꾸는 변수는 질문 분리 하나다. 원 질문의 용어 표기(영어/한국어)를 유지하며,
  한국어 표현을 우선하도록 하던 지시를 제거했다. 언어 변경은 Step 3에서만 수행한다.
- 번역용 prompt와 검증 로직은 승인된 그대로 유지한다. 검증 조건이나 assertion을 완화하지 않고 예시 입력만 교체한다.
- 이번 단계는 수정한 분리용 prompt 전문 보고에서 멈춘다. 실제 생성·번역·검색, 승인 기록 작성은 시작하지 않는다.

## 2026-10-10 생성·번역 실행 승인

- 사용자가 분리용 prompt 4번의 예시를 '10분 준비운동'으로 최종 교체하도록 승인했다.
  안내 문서와 합성 테스트의 대응 예시도 동일하게 교체했다. 번역용 prompt와 검증 코드는 유지한다.
- 수정한 prompt를 다시 보고하지 않고 한국어 36회 생성 → 동결 → 동결 실제 검색어 36회 번역 → 동결을 실행한다.
- 승인 기록에는 이 사용자 메시지와 실행 직전 소스 해시를 연결한다. 두 단계 동결본은 새 경로에 저장한다.
- 대응표·해시·단계별 사용량과 비용 보고에서 멈춘다. 검색·지표 계산·성능 비교는 승인 범위에 포함되지 않는다.

## Phase A 진단과 보류

`validation_audit_v1` 진단과 v1 query/rules 동결본은 그대로 보존한다.
문헌 전용 요청에도 `time_condition` 확인이 적용되고, 후보 운동명·개인 기록 요청·복수 Metric 계약 불일치 등이 발생했다.
문헌 질문 생성과 전체 Phase A 검증 실패를 구분하며 이를 Retrieval 실패나 문헌 근거 부족으로 표현하지 않는다.

**Phase A 출력 계약 재설계는 별도 작업으로 보류, 서비스 기본값은 legacy 유지.**
Retrieval 서비스 기본값도 H0를 유지하고 V2 설정 확정 시 전환한다.

Phase A → initial query 및 legacy deterministic → initial query 연결은 제거한다.
새 실험의 입력은 Router 판정과 무관한 원 질문이다. Phase A 검증·추가 확인 처리,
Grader/Recovery가 사용하는 기존 literature_subquestion과 해석 코드·prompt는 수정하지 않는다.
과거 선택 함수와 준비 스크립트는 진단 보존용이며 새로운 주 조건으로 사용하지 않는다.

## 고정된 비교 순서

| 조건 | Dense | BM25 | 앞 단계 채택 시 비교 기준 |
|---|---|---|---|
| H1 | 원 질문 | 원 질문 | 출발점 |
| Step 2 | Step 2 실제 한국어 검색어 | 같은 한국어 검색어 | H1 |
| Step 3a | 같은 한국어 검색어 | 동결된 영어 번역 검색어 | Step 2 |
| Step 3b | 같은 영어 번역 검색어 | 같은 영어 번역 검색어 | Step 3a |

각 비교에 명세의 채택 기준을 따로 적용한다. 앞 단계 탈락 시 다음 조건을 직전 채택 설정과 직접 비교한다.
Step 3b용 추가 LLM 호출은 없다. 생성·번역 실패 문항도 평가에서 제외하지 않는다.
영어 query를 독립 생성하지 않으며 번역 단계에서는 개인 기록 여부를 다시 판정하지 않는다.

개인 기록 값만 일반 패턴으로 검사하며 연구 조건 숫자는 허용한다.
검출하기 어려운 잔존 문맥과 주제 소실은 검색 전 사용자 대응표 검토로 확인한다.
case ID, 평가 분류, Gold, 정답 chunk, 순위, 지표는 규칙 작성과 검색어 선택에 사용하지 않는다.

## 승인 순서와 미실행 범위

1. 생성·번역 prompt/schema/검증 구현 → 전문과 규칙 보고 → 중단.
2. 사용자 prompt 승인 → 한국어 36회 생성 및 동결 → 동결 실제 검색어 36회 번역 및 동결.
3. 전체 대응표, 두 manifest hash, 단계별 호출·토큰·비용·지연·실패 보고 → 검색 전 중단.
4. 사용자 대응표 승인 → 동결 query만 사용하는 Retrieval 평가. 평가 중 LLM 호출 없음.

metadata는 이번 범위에서 제외한다. 약어·숫자 정규화, child, 후보 깊이 변경,
Phase A 계약 수정, Grader/Recovery 정책 수정과 별도 검증용 평가 질문·Gold 열람을 시작하지 않는다.

## 2026-10-10 대응표 승인과 번역 검증 v2

- 사용자가 전체 대응표와 검색 평가·테스트·commit·task branch push·PR·GitHub Actions 확인을 승인했다.
- `unit_preservation`은 날짜 뒤 일반 영어 단어를 미등록 단위로 인식했다.
  일반 규칙으로 날짜를 단위 짝 검사에서 분리하되 숫자 보존 검사에는 남긴다.
  공백 뒤에는 명시된 단위만 인식하고 숫자에 붙은 미등록 단위 식별자는 그대로 비교한다.
  볼트·암페어의 단위 동의어를 명시하며 실제 단위·숫자·약어 변경 거부를 합성 테스트로 검증한다.
  공백으로 분리된 미등록 단위는 모두 검출하지 못한다는 한계가 있다.
- LLM을 다시 호출하지 않고 동결된 번역 출력 36개를 재검증했다. 번역 출력·원래 호출 provenance는 그대로다.
  `data/evaluation/retrieval_step3_translation_queries_v2/`에 새 version으로 저장하고
  dev HYB-001·006의 실제 사용 검색어만 기존 영어 번역문으로 전환했다. 추가 호출·토큰·비용은 모두 0이다.
- 생성 실패 7건은 실제 개인 문맥 잔존이었다. dev-ko HYB-001·003 및 HYB-007은 검증 통과에도 품질이 미흡하다.
  dev HYB-007도 독립 질문으로서 주제·지칭 관계가 미흡하다. 생성문과 생성 규칙은 변경하지 않는다.
  catalog 형식 검사는 영어 표기만 잡으며 한국어 운동명 잔존을 모두 검출하지 못한다.
- 이전 `HUMAN_REVIEW_NOTES.md`를 덮어쓰지 않고
  `reports/experiments/retrieval_v2_step23_query_revalidation_v2/HUMAN_REVIEW_NOTES.md`에 승인 내용을 기록했다.
- 순서는 H1 재현 → Step 2 → Step 3a → Step 3b이며 기존 채택 기준을 자동 적용한다.
  기준 탈락은 실행 실패가 아니다. 서비스 기본값은 실험 채택 결과와 별개로 legacy/H0를 유지한다.

## 2026-10-10 개발 평가 결정

- H1 재현과 Step 2 문헌 전용 결과 불변은 dev/dev-ko 모두 통과했다.
- Step 2는 모든 사전 기준을 충족해 채택했다. dev EGR 좋아짐/나빠짐/동일은 2/0/16, dev-ko는 1/0/17이다.
- Step 3a는 dev EGR 좋아짐 2건·나빠짐 3건으로 제외했다.
- Step 3b는 직전 채택 설정 Step 2와 비교했으며 dev EGR 좋아짐 1건·나빠짐 2건으로 제외했다.
  dev-ko 개선만으로 사전 채택 기준을 바꾸지 않았다.
- 집계 MRR의 키(`mrr`)와 문항별 키(`reciprocal_rank`) 연결 오류를 수정했다.
  첫 실행에서 저장한 모든 검색 순위를 그대로 사용해 보고 계산만 재개했으며, 중단 자료는 보존했다.
  실제 기존 평가 함수의 schema를 사용하는 합성 회귀 테스트를 추가했다.
- 결과·문항별 변화·분류별 집계와 동결 해시는 `RETRIEVAL_V2_STEP23_RESULTS.md`에 기록했다.
  이후 단계, 서비스 기본값 변경, 별도 검증용 평가와 pgvector 운영 경로 확인은 시작하지 않는다.
