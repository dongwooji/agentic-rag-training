# Step 4 구현 보정·Dense 입력 길이 결과

평가일: 2026-10-10.

**사전 기준에 따른 선택은 Step 3b (128)다.** 서비스 기본값은 legacy/H0를 유지한다. 최종 V2 설정 동결과 운영 pgvector 확인은 후속 단계다.

이번 Step 4는 명세와 다르게 child 50개에서 나온 parent 20~47개를 RRF에 넣은 이전 구현의 보정이다. 기존 child와 embedding은 그대로 재사용했고 고유 parent 10개만 전달했다. 이전 Step 4 결과와 결정을 덮어쓰지 않고 역사적 기록으로 보존한다. 이전 결과를 올바른 parent 10개 조건의 결과로 해석하지 않는다.

[사전 결정](decisions/RETRIEVAL_V2_CHILD_CORRECTION_LENGTH.md)은 검색 전에 고정했다. 세 조건은 각각 Step 3b와 독립 비교하며 누적하지 않는다. Step 3b가 과거 사전 기준을 통과했다는 의미는 아니며, 사용자 승인 사후 기준선이라는 기존 기록을 유지한다.

## 검증

- 관련 단위·통합 테스트 77 passed. 공개 CI 명령 로컬 실행 766 passed / 81 deselected. 로컬 전체 847 passed. 기존 Starlette/AnyIO DeprecationWarning 1건.
- 로컬 수에는 이번 commit에 넣지 않은 사용자 미추적 JATS 테스트 19개가 포함된다. GitHub Actions는 commit된 공개 테스트 전체를 실행한다.
- 보호 대상 491개 파일의 SHA-256 동일 확인. 기존 child·생성·번역·평가와 새 embedding·평가 manifest의 모든 산출물 해시 검증 성공.
- Step 3b 순위·점수·지표 재현 성공. 세 조건 BM25 순위·점수 동일, 실제 RRF Dense/BM25 parent 입력 모두 10개 확인.
- 합성/mock 테스트와 별도로 실제 pinned MiniLM·frozen corpus v1·dev/dev-ko 검색 평가를 실행했다. 모든 조건의 순위를 저장한 뒤에만 Gold를 읽었다.
- LLM 호출 0회 / 토큰 0 / 비용 $0 / 실패 호출 0. DB·API 호출 없음. secrets 파일을 읽지 않았다. held-out 질문·Gold 열람/실행 없음.
- 256 첫 준비 실행은 embedding과 manifest 동결 후 마지막 로그 출력에서 인자 오류가 났다. 이 v1을 보존하고 출력 코드 수정 뒤 v2로 새로 계산했다. 두 embedding의 차이는 1e-6 이내이며 완료 출력까지 검증하는 합성 테스트를 추가했다. 성능 평가에는 정상 완료한 v2만 사용했다.
- 길이 진단 중 tokenizer의 최대 길이 경고가 있었지만 실제 encoder 입력은 선언된 길이로 잘린다. 준비 실행에 길이를 넘는 원문을 그대로 forward한 것은 아니다.
- 기존 parent·embedding·query·Gold·H0/H1·역사적 결과는 수정하지 않았다. 새 조건 선택은 서비스 기본값 전환이나 최종 V2 freeze를 의미하지 않는다.
- BGE-M3 등 모델 교체와 child 벡터 결합은 향후 과제로만 기록했다. metadata·추가 후보 깊이·Recovery·근거 결합·운영 pgvector·held-out 평가는 시작하지 않았다.
- 두 평가셋은 대응 질문이다. 36회 개발 측정을 독립 일반화 성능으로 표현하지 않는다.
