# 로컬 API의 한국어 질문 지원

실제 API에서 발견한 표현 차이를 처리하기 위해 실행용 Router와 한국어 입력
어댑터를 추가했다. 이는 동결 평가 이후의 사용성 변경이며, 기존 평가 수치의
개선으로 해석하지 않는다.

## 지원하는 표현

| 입력 표현 | 처리 |
|---|---|
| 내 기록, 제 운동 기록, 저의 훈련 로그 | 개인 기록 요청 인식 |
| 내 데드리프트, 제 벤치프레스, 나의 스쿼트 | 개인 운동 기록 요청 인식 |
| 데드리프트 / 데드 리프트 | Deadlift (Barbell) 후보로 변환 |
| 벤치프레스 / 벤치 프레스 | Bench Press (Barbell) 후보로 변환 |
| 스쿼트 / 스쾃 | Squat (Barbell) 후보로 변환 |
| 인클라인 벤치프레스 | Incline Bench Press (Barbell) 후보로 변환 |
| 시티드 바벨 숄더프레스 | Seated Shoulder Press (Barbell) 후보로 변환 |
| 처음 3세션, 첫 세 세션, 마지막 세 세션 | 기존 N-session 입력 형식으로 변환 |
| 주간 훈련량, 주간 볼륨, 주별 훈련량 | 기존 weekly_volume 연산 사용 |
| 주간 빈도, 주별 수행 횟수 | 기존 weekly_frequency 연산 사용 |
| 운동 공백, 훈련 공백 | 기존 training_gap 연산 사용 |
| 추정 1RM, 중앙값 | 기존 e1RM / median 표현으로 변환 |

숫자로 지정한 세션 수 및 한글 수 표현 한/두/세/네/다섯/여섯/일곱/여덟/아홉/열을
지원한다. `3회`는 세트 수와 구분할 수 없으므로 세션 수로 자동 해석하지 않는다.
날짜는 기존 ISO 형식(예: 2018-01-01)을 사용하며 상대 날짜를 임의로 계산하지 않는다.

## 동작과 경계

- Router는 원래 질문에서 의도를 판단한다. 한글 운동명이 문헌 질문에 등장했다는
  이유만으로 개인 기록 도구를 추가하지 않는다.
- 한국어 변환은 구조화 도구 입력 추출에만 적용한다. 원래 질문, 초기 문헌 검색
  질의와 문헌 판정/복구 흐름은 그대로 사용한다.
- 변환한 운동명 후보는 기존 Resolver가 DB의 정식 운동명과 대조한다. 없는 운동은
  실패하며, 덤벨/루마니안/스모 등 명시된 다른 장비·변형을 바벨 기본 운동으로
  자동 대체하지 않는다.
- 지원하는 일반 운동명은 위 표의 바벨 운동 후보에 연결된다. 목록 밖 운동이나
  오타까지 모두 지원하는 자유로운 한국어 해석기는 아니다.
- 현재 도구 입력 구조는 요청당 하나의 운동과 하나의 Metric 연산을 지원한다.
  여러 운동/명시적 지표 또는 서로 다른 처음·최근 세션 수는 임의로 하나를 선택하지
  않고 구조화 오류로 종료한다. 질문을 나눠서 요청한다.
- 세션·운동명·지표 표현을 규칙으로 처리할 수 있으면 Resolver의 LLM 호출은 없다.
  그 밖의 입력은 기존 입력 추출 provider와 typed 검증 경로를 사용한다.
- 원래 질문, 변환된 질문, 적용한 별칭, 입력 언어 설정 해시를 내부 출처 정보에
  보존한다. API 응답에 비밀값을 추가하지 않는다.

## Swagger 예시

```json
{"question": "내 데드리프트의 처음 3세션과 최근 3세션의 median e1RM을 비교해줘."}
```

```json
{"question": "제 벤치프레스의 주간 훈련량을 계산해줘."}
```

```json
{"question": "내 데드리프트의 처음 세 세션과 최근 세 세션의 추정 1RM 중앙값을 비교하고, 점진적 과부하 문헌을 설명해줘."}
```

적용하려면 현재 Uvicorn 프로세스를 Ctrl+C로 종료하고 기존 실행 명령으로 다시
시작한다. 이미 초기화된 서버는 이전 Router와 Resolver를 메모리에 보관한다.

## 구현과 검증

- `config/runtime_input_language_v1.json`: 실행용 표현/별칭 목록.
- `src/routing/runtime_language.py`: 운동명·세션·지표 표현 변환.
- `src/routing/runtime.py`: 실행용 개인 기록 및 지표 의도 규칙.
- `src/graph/runtime_tool_input_resolver.py`: 기존 Resolver에 변환 입력 연결.
- `src/api/dependencies.py`: 실제 API 구성 시 위 어댑터 주입.
- `tests/test_runtime_korean_input.py`: 한국어 변형, 부정 사례, 입력 검증,
  mock 그래프 경로, API 구성과 기존 파일 해시 검증 43개.

초기 한국어 입력 어댑터는 352 passed, Phase A.1은 417 passed였으며, 현재 Phase A.2까지 포함한 로컬 전체 검증은 468 passed이다. DB/API 실호출과 baseline 재평가는 수행하지 않았다.
기존 Router/Resolver 구현과 설정, 전처리 별칭, 동결 v1/v2 산출물은 보존했다.

위 표는 legacy runtime의 연결 정책이다. 선택형 Phase A/A.1 경로는
[질문 해석 안내](QUESTION_INTERPRETATION.md)를 참고한다. 생략된 운동명을 특정 장비로
연결하는 legacy 정책은 그대로 남아 있다. Phase A.2에서는 운동 후보 선택 후 명시적 공동 조회와
인클라인/로우의 생략명 제한을 적용한다. 기존 통합 데이터의 분리 조회는 구현하지 않았다.

## Phase A.2 안내

Phase A의 운동 모호성은 자동 병합 대신 [후보 선택 흐름](EXERCISE_CLARIFICATION.md)으로 처리한다.
덤벨 해머컬처럼 명확한 표현은 해당 기록만 조회한다. 기존 단계의 공동 조회 설명은 이전 정책이다.
